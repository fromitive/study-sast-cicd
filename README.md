# AI 보안 자동화 하네스

핀테크 서비스를 두 축으로 자동 점검한다. 둘 다 `claude -p`(Claude Code 구독)
위에서 돌아가 **호출당 API 과금이 없다.**

- **런타임 레드팀** (`harness.py`) — 배포된 챗봇/AI 기능을 공격해 정보 유출·금지 행동을 찾는다.
- **코드 SAST** (`sast.py` + `agent_audit.py`) — 코드에서 취약점을 찾는다. 아래가 이 문서의 핵심.

---

## 왜 스캐너만으론 부족한가 (이 프로젝트의 핵심 원리)

보통 SAST 도구(Semgrep·Trivy·Gitleaks)는 **"정해진 나쁜 모양"을 찾는다.**
`eval(사용자입력)`, 하드코딩된 비밀번호, 취약한 라이브러리 버전처럼
"이런 패턴이면 위험"이라는 **규칙 목록**에 맞춰 코드를 훑는 방식이다.

이 방식은 싸고, 빠르고, 매번 같은 결과가 나온다. 하지만 결정적 약점이 있다.

> **규칙에 없는 건 통째로 못 본다.**

특히 **코드 한 줄 한 줄은 멀쩡한데 조합·설계가 잘못된 결함**을 놓친다:

- 남의 데이터에 접근되는데 권한 검사가 빠진 경우 (IDOR)
- 같은 기능인데 한쪽 함수만 검사하고 형제 함수는 안 하는 경우
- "게스트는 격리돼 있다"처럼 신뢰 경계를 착각한 경우

이런 건 특정 "나쁜 모양"이 없다. 문법상 다 정상이라 스캐너 규칙으로
표현이 안 되고, 그래서 스캐너는 **존재조차 모른다.**

### 실제 사례 — 스캐너가 절대 못 잡는 결함

Apple의 컨테이너 런타임에서 나온 실제 취약점(CVE-2026-64777)이 딱 이 경우다.
한 파일 안에서 `walk()`라는 함수는 링크가 실제로 어디를 가리키는지까지 확인하는데,
형제 함수 `read()`·`info()`는 그 확인을 빠뜨렸다. 세 함수 다 문법은 멀쩡하다.
스캐너 규칙에 걸릴 게 없다. 하지만 이 **"같은 파일 안의 비대칭"**이
호스트 파일 유출로 이어지는 결정적 단서였다.

---

## 어떻게 풀었나 — 탐지를 에이전트화

규칙 매칭으로 안 되면, **사람 감사자가 하듯 코드를 "읽고 추론"하게** 만들면 된다.
그게 `agent_audit.py`다. 사람이 코드를 감사하는 절차를 세 역할로 나눴다.

```
  recon      레포를 훑어 "어디부터 볼까" 우선순위 큐를 만든다
    │        (인증·경로처리·외부입력·명령실행에 닿는 파일을 위로)
    ▼
  auditor    파일마다 3단계로 본다
    │          1) 위협 후보 훑기
    │          2) 진짜 도달 가능한가 + 위에서 막는 검사가 있나
    │             + ★같은 파일에 '비대칭'이 있나 (한쪽만 검사·다른쪽 누락)
    │          3) 살아남은 것만 finding으로 기록
    ▼
  verifier   전체 finding을 다시 보고 오탐 제거 + 심각도 확정
```

`auditor`의 2단계에 위 사례의 교훈을 규칙으로 박아뒀다 —
**"같은 액터·같은 신뢰 경계인데 한쪽에만 방어가 있으면, 그건 설계 의도가 아니라
누락일 확률이 높다."** 그래서 이 파이프라인은 스캐너가 못 보는 비대칭형 로직
결함을 후보로 올릴 수 있다.

### 그래도 사람이 필요하다 (정직한 한계)

에이전트가 만능은 아니다. 위 Apple 사례에서도 실제 AI 파이프라인은 근본 원인
(검사가 이름만 보고 실제 파일은 안 본다)까지는 스스로 도달했지만, 그걸 **완전한
파일 유출 공격으로 조립하고 심각도를 제대로 매긴 건 사람**이었다. 에이전트는
비결정적이라 매번 결과가 다르고, 심각도를 과소평가하기도 한다.

그래서 이 프로젝트의 결론은 **셋을 겹치는 것**이다. 하나가 다른 걸 대체하지 않는다.

| 층 | 담당 | 잘하는 것 | 못하는 것 |
|---|---|---|---|
| 스캐너 (`sast.py`) | 알려진 나쁜 패턴 | 싸고·확실·재현됨 | 로직/설계 결함 |
| 에이전트 (`agent_audit.py`) | 코드 추론 | 패턴 없는 로직 결함 | 비결정적·심각도 오판 |
| 사람 | 최종 검증 | 심각도 확정·공격 조립 | 대량 반복 |

## 실행

기본 백엔드는 Claude Code CLI(구독 인증 → 과금 없음).
사전: `npm i -g @anthropic-ai/claude-code && claude login`

```bash
# 스캐너만 (알려진 패턴)
pip install semgrep                       # trivy/gitleaks는 별도 설치(없으면 skip)
python sast.py --target ./samples

# 스캐너 + 에이전트 로직 감사 (권장)
python sast.py --target ./myrepo --agent --report out.json

# 에이전트 감사만 단독으로
python agent_audit.py --target ./myrepo

# 런타임 레드팀 + 회귀 게이트
python harness.py
python regression.py
```

API 백엔드(과금)로 바꾸려면: `LLM_BACKEND=api ATTACKER_MODEL=<full-model-id> ...`

CI에서 CLI 백엔드를 쓰려면 `claude setup-token`으로 장수명 토큰을 발급해
CI 변수로 주입한다(구독 필요). 자세한 잡 구성은 `.gitlab-ci.yml` 참고.

## 파일

| 파일 | 역할 |
|---|---|
| `harness.py` | 런타임 레드팀 루프 (공격자→타깃→judge) + LLM 백엔드 스위치 |
| `regression.py` | 뚫린 케이스 회귀 재검증 (배포마다, 재발 시 CI 차단) |
| `objectives.json` | 레드팀 목표 — 우리 앱이 하면 안 되는 것 |
| `sast.py` | 스캐너 탐지 + LLM 트리아지 (+`--agent`로 에이전트 패스 연결) |
| `agent_audit.py` | 에이전트 로직 감사 (recon→auditor→verifier) |
| `samples/vuln.py` | 데모용 취약 샘플 |
| `.gitlab-ci.yml` | 파이프라인 (신규는 로깅, 회귀는 게이트) |

> ⚠️ 본인이 테스트·감사 권한을 가진 대상에만 사용. 타사 모델 가드레일 우회 도구가 아니다.
